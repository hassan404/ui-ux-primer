# Delivery — the form the course should take

*How the course reaches the learner. Grounded in [raw/09-delivery-formats.md](raw/09-delivery-formats.md); decided against the objectives ("the course itself is the UX").*

---

## 1. What the evidence constrains

Three facts from the research narrow the field before any preference enters:

1. **Visual judgement is a perceptual skill, and perceptual skills have a known training format.** Kellman's Perceptual Learning Modules — validated in aviation, dermatology, mathematics — are many short classification trials, immediate feedback, high stimulus variation, adaptive difficulty. Can't Unsee arrived at the same design independently. A course teaching *the eye* should look like this, not like a lecture. *(raw/09 §2E)*
2. **Completion is the metric, and short-finite beats long-gamified.** MOOC completion is single-digit; short interactive courses complete. Streaks and SRS create review debt that contradicts the "one evening" promise — quarantine them. *(raw/09 §2F, §3.4)*
3. **Production cost is what kills beautiful courses.** Distill died of 50+ editorial hours per article; Nicky Case's masterpiece is 4,400 words on off-the-shelf libraries; Red Blob Games ships a house style of reusable diagram archetypes. Build archetypes, not bespoke widgets. *(raw/09 §3.1)*

## 2. The contenders

| Option | Teaches noticing? | Build cost | Verdict |
|---|---|---|---|
| GitBook / plain docs site | No — reading about seeing isn't seeing | ~0 | Substrate only, not sufficient |
| Video course | No — passive, unskimmable, ages badly | Medium-high | Rejected |
| Anki/SRS deck | Weakly | ~0 | Rejected as core (review debt); fine as export |
| Flashcard-style fullstack app | Partly — but flashcards test recall, and our skill is *discrimination* | High | Rejected as framing |
| Full Execute-Program-style adaptive platform | Yes | Very high (30–60 dd) | Rejected for v1; the trainer (below) is the 20% of it that matters |
| Ciechanowski-grade explorables | Yes | Extreme | Copy the discipline, not the fidelity |
| **Interactive MDX site + reusable drill archetypes** | **Yes, directly** | **Low-medium, bounded** | **Chosen** |

## 3. The recommendation: three layers

**Layer 1 — the repo is the free tier.** The full course prose lives as CC-licensed Markdown in this repository, readable end-to-end on GitHub. Zero build cost, maximum reach (the 185k-star YDKJS effect), community translation for free. Constraint honored: even the plain-text edition must be complete and excellent alone.

**Layer 2 — the course: a static MDX site with six interaction archetypes.** Next.js/MDX (or Astro), statically hosted. All interactivity comes from six reusable components, instantiated by config — never bespoke:

1. **A/B commit → overlay-flicker reveal** — the Can't Unsee mechanic. Forced binary commitment, then an in-place toggle that exploits change-detection psychophysics. Replaces every side-by-side before/after in the course. *(~2–4 dd)*
2. **Predict-then-reveal** — commit to an answer before the explanation unlocks. The cheapest active-learning wrapper there is. *(~1–2 dd)*
3. **Single-variable slider over live UI** — drag padding/weight/contrast/radius through its range; feel where "right" lives. *(~2 dd)*
4. **Annotated before/after pair with a named rule** — the Refactoring UI unit, as a component. *(~1 dd)*
5. **Spot-the-flaw click target** — click where the bug is; objectively scoreable. *(~2 dd)*
6. **Fix-the-layout with a checker** — contrast math, spacing-scale conformance, alignment tolerance: graders that already exist and make lessons self-checking. *(~3–5 dd)*

Total interactive budget: **~10–20 dev-days**, after which every lesson's interactivity is a data file.

**Layer 3 — the radical bet: the discrimination trainer.** The strongest original idea in the research *(raw/09 §3.2)*: because the course's UI examples are **rendered from design tokens, not screenshots**, the "wrong" variant of any example can be generated by programmatically perturbing exactly one token — padding off-scale, type ratio broken, misalignment by 3px, contrast under 4.5:1. Consequences: an infinite, non-memorizable item pool; **objective auto-grading of a "subjective" skill** (the system knows what it broke, so it can score *and explain*); perturbation magnitude as a difficulty dial (exactly what Kellman's research requires). No existing product does this for UI design. Shipped as the *optional post-completion appendix* — "you've finished; now train the eye 60 seconds a day if you want" — so it never threatens the completion promise. *(~8–15 dd, only after Layers 1–2 ship)*

## 4. Design commitments (the course as its own proof)

- **Finite and honest:** ~3 hours, a visible progress map, no artificial gating, quit-anytime with nothing lost.
- **Word budget in CI:** ≤1,200 words/module; the build fails if prose bloats.
- **Attention direction over widget fidelity:** the sentence telling you *where to look* is the product; the widget is the occasion. *(raw/09 §3.9)*
- **Hierarchical review, free:** later exercises silently re-exercise earlier modules (the settings-page build re-tests spacing and hierarchy) — a syllabus rule, not a feature. *(raw/09 §3.8)*
- **A printable one-page "visual tells" checklist** as the artifact that outlives the course. *(raw/09 §3.10)*
- **Accessible by construction:** keyboard-first drills, visible focus, honest contrast — a design course that fails its own module 9 is dead on arrival.

## 5. Build path

| Phase | Deliverable | Effort |
|---|---|---|
| 1 | Course prose, all 10 modules, in the repo (Layer 1 complete) | writing time |
| 2 | MDX site + archetypes 2 & 4 (predict-reveal, before/after) — course is already teachable | ~4 dd |
| 3 | Archetypes 1, 3, 5, 6 — full interactivity | ~10 dd |
| 4 | Token-perturbation trainer (Layer 3) | ~8–15 dd |

Each phase is independently shippable; the course is never blocked on the bet.
